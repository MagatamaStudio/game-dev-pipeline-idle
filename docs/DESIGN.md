# 设计文档 · 游戏开发流水线

## 1. 一句话

一款关于「做游戏」的增量放置游戏：你经营一家工作室，从 1972 年的车库一路做到 2022 年的服务型时代。核心不是点点点，而是**让一条开发流水线保持平衡**。

## 2. 为什么是流水线，而不是一台更大的点击器

常见的增量游戏是「点击 → 资源 → 买更快的产出 → 点击」的单变量循环。它的问题是中后期玩家只剩下一件事：无脑买最便宜的那个升级。

「做游戏」这件事本身是**有工序**的：先有概念，才能编程；先有代码，才能上美术；做完还要测。把它建模成流水线，会自然长出三个决策：

1. **该补哪个部门** —— 整条线的速度由最慢的部门决定（约束理论）。
2. **要不要并行** —— 只有一个项目槽时，一部作品必须走完全部工序才能开始下一部；加槽位让多部作品同时卡在不同工序上。
3. **要不要为全局付溢价** —— 工具只提升单部门，引擎提升所有部门但更贵。

这三个决策互相牵制，而且**每次升级后的最优解都会变**，这就是持续游玩的动力。

## 3. 三层循环

| 层级 | 时间尺度 | 玩家在做什么 | 反馈 |
|------|----------|--------------|------|
| 瞬时 | 0–10 秒 | 点「灵感迸发」，盯瓶颈部门 | 产能条翻倍、进度条变快 |
| 中程 | 30 秒–5 分钟 | 招人 / 买工具 / 扩槽，平衡流水线 | 作品一部部发行，收入跳涨 |
| 长程 | 一轮 12–25 分钟 | 完成时代目标 → 换代 → 花传承点 | 时代主题、文案、新部门 |

## 4. 时代表

每个时代由 `js/config.js` 里一条数据定义：新的部门数量、每个部门的工序时长、工资、工具、引擎、槽位、目标、以及文案和作品名词库。

| 时代 | 部门 | 工序总时长（1 人/部门时） | 目标 | 专属机制 |
|------|------|--------------------------|------|----------|
| 1972 街机黎明 | 概念 5s、程序 12s | 17s | 10 部 | — |
| 1985 8 位家用机 | 概念 6s、程序 9s、美术 7s、音效 4s | 26s + 出厂 8s | 14 部 | 卡带产线 |
| 1995 16 位与 PC | +测试 4s | 33s | 17 部 | 外包 |
| 2005 3D 与在线 | 五部门，比例重排 | 29s | 19 部 | — |
| 2013 移动与独立 | 测试改为「运营」 | 29s | 21 部 | — |
| 2022 服务型时代 | 改为「长线运营」 | 29s | 24 部 | — |

时代之间的「变大」不靠让玩家等更久，而是靠 `eff`（单人产能）和 `price`（作品售价）同步放大：第六时代一个员工每秒干 12000 点活，一部作品卖 $120,000。玩家看到的数字越来越大，节奏却保持一致。

## 5. 数值模型

### 5.1 产能

```
部门产能 = 人数 × 时代效率 × 工具倍率^等级 × 引擎倍率^等级 × 传承加成 × 迸发加成
```

### 5.2 吞吐

一条流水线的产出受三个上限约束，取小：

```
吞吐（部/秒） = min(
    最慢部门的 1/耗时,
    槽位数 / 单部作品总耗时,
    1 / 产线耗时          // 只有带产线的时代才有这一项
)
```

只买一个槽位时，一部作品必须串行走完所有工序，第二项生效；槽位足够多时，瓶颈部门决定一切。这个公式让「扩槽」在早期收益极高、后期收益递减，形成自然的阶段感。

### 5.3 费用曲线

| 项目 | 成本增长 | 效果 | 设计意图 |
|------|----------|------|----------|
| 员工 | ×1.40 / 人 | +1 人（线性产能） | 现实里团队规模有上限 |
| 工具 | ×2.00 / 级 | 该部门 ×1.70 | 指数成长的主引擎 |
| 引擎 | ×2.20 / 级 | 全部门 ×1.30 | 一次性大件，攒钱的理由 |
| 项目槽 | ×1.90 / 个 | +1 并行 | 前期强、后期饱和 |

所有初始费用都以「该时代开局每秒收入」为基准换算成秒数（员工 20s、工具 70s、引擎 60s、槽位 50s），所以六个时代的**体感节奏一致**，只有量级不同。

### 5.4 收入与声望

```
单部收入 = 售价 × 作品规模 × 质量(1.00–1.25 随机) × (1 + √声望 × 0.035)
```

声望只带来温和的乘数（100 点声望约 ×1.35），避免「声望滚雪球」把平衡彻底冲垮。

### 5.5 实测节奏

用 `tools/sim.js` 里的贪心 AI（每次买「每块钱提升吞吐最多」的升级）跑出来的结果：

| 时代 | 首轮耗时 | 传承 +N |
|------|----------|---------|
| 1972 | 1m45s | +5 |
| 1985 | 4m04s | +7 |
| 1995 | 4m24s | +9 |
| 2005 | 4m29s | +10 |
| 2013 | 5m03s | +12 |
| 2022 | 5m47s | +15 |
| **合计** | **25m33s** | |

带上传承加成跑第二轮约 **13m56s**。改完数值后重跑这个脚本，确认每个时代仍落在 2–6 分钟区间。

### 5.6 时代专属机制

前几个版本里每个时代只是「换了皮肤」：部门更多、数字更大，玩法没变。现在 1985 和 1995 各有一个真正的机制。

**1985 · 卡带产线**

做完的作品不能直接卖，要先排进「出厂」队列，一片片压成卡带。产线本身是流水线的最后一道工序，耗时 = `1 / 产线速率`，所以它和别的部门一样进瓶颈计算，可以花钱扩产线（×1.6/级）。

> 设计上踩过一个坑：最初把产线做成「全局产出上限」，结果它在和「并行项目槽」耦合——买了产线但槽位还卡着，等于白买；买了槽位但产线还卡着，也等于白买。玩家会同时遇到两个都「差一点」的升级，体验极差。改成一道普通工序后，任何一次投入都能立刻反映在吞吐上，联动关系变简单了。

**1995 · 外包**

每个部门下方有一个「外包」按钮，价格 = 该部门所有在制项目的剩余工作量，折算成这些作品约 55% 的收入。按下去，整个部门的积压瞬间清空，项目直接进入下一道工序。

它的作用不是「更强」，而是「止损」：当某部大制作卡在最后一个部门、而你已经等不及想进下一个时代时，花钱买时间。因为单价定得比正常产出贵（55% 收入换省下的时间），理性玩家只会在关键时刻用。

## 6. 传承（Prestige）

进入新时代时：

- 资金、团队、工具、项目槽、声望**全部清零**
- 获得传承点：`2 + √(本时代发行数) × (1 + 时代序号 × 0.35)`
- 传承点永久保留，可投资四项：

| 传承 | 效果 | 上限 |
|------|------|------|
| 启动资金 | 开局多 `时代售价 × 2 × 等级` 美元 | 12 |
| 方法论 | 全部门产能 ×(1 + 0.12×等级) | 12 |
| 远程办公 | 离线效率 50% → 98% | 6 |
| 核心班底 | 每部门开局自带 1+等级 人 | 6 |

走完第六个时代后，带着全部传承回到 1972（第二轮），形成真正的重复游玩循环。传承点的设计是「够买一两项，但买不全」，逼迫玩家每轮选不同路线。

## 7. 离线与存档

- **离线**：读档时用离开时长（上限 8 小时）按 50% 效率重放流水线，步长 5 秒。8 小时的模拟耗时约 4ms。
- **切标签页**：回到页面时按 100% 效率补齐（不惩罚短暂切走），上限 8 小时。
- **存档**：`localStorage` 每 8 秒、切后台、关闭页面时写入；支持导出为 Base64 文本跨设备迁移。读档时做完整的字段校验与修复，坏档不会白屏。
- 时间戳用 `Date.now()`，防篡改不是目标 —— 单机游戏，改档是玩家的自由。

## 8. 技术方案

**零构建、零依赖、纯静态。**

- 没有打包器、没有框架、没有 CDN 依赖，`index.html` 双击就能跑，GitHub Pages 直接托管仓库根目录。
- 用普通 `<script>` 而不是 ES Module：`file://` 协议下也能直接打开调试。
- 逻辑与渲染彻底分离：`engine.js` 不引用任何 DOM，所以能在 Node 里被模拟器直接驱动、被测试直接断言。
- 渲染分两条路径：结构变化时重建 DOM（换时代、页签切换），每帧只更新文本和进度条宽度，10Hz 刷新，性能开销可忽略。
- 存档只存状态，不存派生值；所有产能、费用、吞吐都在读取时按公式算出来，改数值不会让老存档失真。

**已实现**

- 六时代完整流程 + 换代传承 + 第二轮循环
- 五部门流水线、瓶颈提示、并行槽位
- 工具 / 引擎 / 团队三条升级线
- 1985 卡带产线、1995 外包两个时代专属机制
- 灵感迸发（主动技能）
- 离线结算、自动存档、导入导出、重置
- 桌面与移动端布局、六套时代配色
- 43 项引擎逻辑测试 + 40 项浏览器端测试

**下一步可以加**

1. **补齐后面三个时代的专属机制**：
   - 2005：**服务器** —— 按在线人数持续烧钱，也持续收订阅费
   - 2013：**内购** —— 放弃单份售价，换取随留存增长的长尾收入
   - 2022：**赛季** —— 周期性全局 buff，要求玩家规划节奏
2. **随机事件**：主机换代、盗版潮、爆款、裁员，给每轮不同的节奏。
3. **作品档案**：记录每部作品的名称、评分、销量，做成一个可翻阅的「作品集」。
4. **成就 / 统计**：给重复游玩一个额外目标。
5. **平衡工具**：把模拟器做成可视化曲线，直接对比不同策略的收入曲线。

## 10. 怎么加一个时代

在 `GD.ERAS` 里追加一条数据即可，不需要改引擎：

```js
{
  key: 'vr', year: '2030', name: '空间计算',
  price: 900000, eff: 90000, startCash: 1200000,
  stages: [ { id:'concept', name:'概念', icon:'✎', need: 450000 }, ... ],
  wages: { concept: 1300000, ... },
  wageGrowth: 1.18,
  tools: [ { id:'g_concept', stage:'concept', name:'…', mult:1.7, cost: 4600000 } ],
  engine: { name:'…', mult:1.3, cost: 16000000 },
  slotCost: 3200000, slotGrowth: 1.9,
  goal: { releases: 26 },
  words: { pre: [...], post: [...] }
}
```

加完跑 `node tools/sim.js` 确认新时代的耗时和传承收益落在曲线上。
